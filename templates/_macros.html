{# Reusable card/badge macros (§6.5). tool_card is imported by home/category/404; processing_pill additionally by tool/tool-multi/tool-text (the trust badge) and by about/privacy (which describe the badge, and must not re-invent it); ad_slot by those same three tool templates (Phase 9 §3.1). All StrictUndefined-safe: name/slug/type/input_format/output_format/category are guaranteed on every tool dict; `tagline` is guarded with dict .get so a future tagline-less tool can't crash the build. #} {# processing_pill(tool) — Local (client-side, green) / Cloud (server-side, blue) with a tooltip (P13/P14). This is the first visual treatment for the .card--server conditional, and the single source of truth for the badge: about/privacy render it rather than describing a badge by name, which is how the three vocabularies (Local/Cloud vs Client-Side/Server-Side vs the long phrases) drifted apart in the first place. `tool` only needs a `type` key, so pages with no tool in scope can call this with a literal — processing_pill({'type': 'server-side'}). Dict access works because Jinja falls back from getattr to __getitem__. These are deliberately NOT modifiers of a base `.badge` class (P13). The old `.badge` pill was green for every case, which is precisely what let the server-side card on about.html render identically to the client-side one; it has since been removed entirely. #} {% macro processing_pill(tool) -%} {%- if tool.type == 'server-side' -%} Cloud {%- else -%} Local {%- endif -%} {%- endmacro %} {# ad_slot(adsense, slot) — ONE AdSense unit, or nothing at all. `slot` is a key of adsense.slots ('leaderboard' | 'in_content'); the element id and the modifier class are both derived from it, so the three tool templates cannot drift apart the way they did before Phase 9 §2 (tool.html guarded its slots, tool-multi/tool-text did not, and 11 of 34 pages shipped blank gaps). This is the single source of truth for slot markup — do not inline it anywhere. `adsense` is passed in rather than read as an env global on purpose: an imported macro sees globals but not the caller's context, so reading it implicitly would silently render nothing the day it moves into the render context. Rendering nothing is exactly the failure this macro exists to prevent, and it raises no error. Renders nothing unless the toggle is on AND both ids are usable. A half-configured overlay (enabled, publisher set, slot id blank) would otherwise emit ``, which fails opaquely at Google's end. generate_headers() widens the CSP on `adsense.enabled` alone, so the half-configured case is the one where the two conditions differ: the CSP opens without a unit to justify it. That is the strictly safer direction — an ad origin allowed but never contacted — and the alternative (emitting a broken unit to match the CSP) is worse. Both ids are attribute-injected, which is why site_settings.py validates publisher_id as `^ca-pub-\d{16}$` and slot ids as `^\d+$` — neither can carry a quote or an angle bracket, and Jinja autoescapes regardless. Never relax those regexes to accommodate a "special" id; fix the id. #} {% macro ad_slot(adsense, slot) -%} {%- set slot_id = adsense.get('slots', {}).get(slot, '') -%} {%- if adsense.get('enabled') and adsense.get('publisher_id') and slot_id -%} {%- set name = slot|replace('_', '-') -%}
{%- endif -%} {%- endmacro %} {# tool_card(tool, cat_id) — the SMALL card used on home + 404. All new inner structure gets its own classes so the base .card rule stays content-agnostic (R12); pass the category id explicitly from the home/category loops, else the macro falls back to tool.category (equal to the id — verified). #} {% macro tool_card(tool, cat_id='') -%} {%- set cid = cat_id or tool.category -%} {{ tool.name }} {%- if tool.get('tagline') %} {{ tool.tagline }} {%- endif %} {{ processing_pill(tool) }} {%- endmacro %}
